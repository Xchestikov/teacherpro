# Браузерные тесты TeacherPro (локально, без Vercel)

Тесты используют реальный Chromium (Playwright) и **изолированную подмену Supabase**. Данные приложения сохраняются только в тестовом `localStorage` браузера. **Реальные аккаунты, PostgreSQL и Vercel не затрагиваются.**

## Подготовка

В терминале из корня локально клонированного репозитория переключись на ветку:

```bash
git fetch origin
git switch audit/pre-release-2026-10
npm install --no-save @playwright/test
npx playwright install chromium
```

Отдельно запусти локальный статический сервер из корня репозитория:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Во втором терминале:

```bash
npx playwright test tests/browser.spec.js --reporter=list --workers=1
```

Проверки открывают `http://127.0.0.1:4173`, автоматически создают два **фиктивных** тестовых аккаунта с доменом `.test`, проходят действия в настоящем браузере и сохраняют изображения в `test-results/`.

### Покрытие

- Вход/выход A→B→A, отсутствие смешивания данных учеников, сохранение через тестовую синхронизацию.
- Создание ученика с датой рождения, виджет дней рождения.
- Выбор фона и бордовой темы в настройках.
- Оплаченный абонемент, проведённый урок 09:45 и списание одного занятия.
- Основные шесть разделов на 320 / 360 / 390 / 768 / 1280 px; горизонтальное переполнение страницы и скриншоты.

### Ограничения

- **Это браузерные тесты с подменой SDK, а не E2E реального Supabase Auth.** Реальные email, SMTP, политики RLS, сеть и работа на двух устройствах требуют отдельных тестовых учётных записей.
- Playwright и зависимости устанавливаются только в локальном клоне. Файлы `tests/` не подключаются в `index.html` и не применяются к production.
- Публикация не выполняется. Не запускай тесты против production-сайта: тесты ожидают локальный адрес и фиктивный Supabase.
- CSS-скриншоты проверяются визуально человеком; автоматизированный тест лишь ловит горизонтальное переполнение и ошибки JavaScript.
- Загрузка шрифтов и внешних ресурсов зависит от доступности Google Fonts.
- Скриншоты `test-results/` не следует коммитить, если на них появляются персональные данные.

После прогона проверь скриншоты, особенно календарь (события :45 и пересечения), виджеты, таблицы, модальные окна, прокрутку, читаемость тёмной и бордовой тем. **Отчёт о прогоне корректно считать пройденным только при наличии фактического вывода Playwright.**
