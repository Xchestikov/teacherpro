## Исправлено в ветке аудита

1. **ID учеников.** Защищена совместимость числовых ID со связями `clientId` в занятиях и оплатах. Генерация нового ID проверяет занятые значения. Уроки по-прежнему имеют независимые UUID.
2. **Финансовая история.** Запрещено задним числом менять сумму уже полученной предоплаты вместе с ценой абонемента. Добавлена валидация суммы и точности до копеек.
3. **Учет выполненных занятий.** Изменение даты проведённого занятия выполняет возврат старого списания и пробует списать по новой дате. Если абонемент не подходит, весь объект данных откатывается.
4. **Синхронизация.** При ручном выборе облачной версии метаданные локального черновика не удаляются заранее. Маркер `dirty` пишется до локального JSON, уменьшая риск тихой потери правок при сбое вкладки.
5. **Приватные данные и HTML.** Улучшено экранирование имён в списках/дашборде/селектах, разрешённые ссылки на материалы дополнительно проверяются при выводе, неиспользуемый токен Telegram-бота исключён из нормализованных данных/новых резервных копий.
6. **Импорт резервной копии.** Файл проверяется на тип структуры и размер (до 20 МБ), некорректные элементы коллекций отфильтровываются, ошибки FileReader обрабатываются явно.
7. **Календарь.** Несколько занятий в одном часовом блоке размещаются рядом, а высота компактных карточек не должна обрезать события, начинающиеся в `:45`.
8. **Доступность.** Добавлены `role=dialog`, `aria-modal`, подпись кнопки закрытия, Escape и фокус на кнопке закрытия модального окна.
9. **Service Worker.** Кешируются только заранее известные статические ресурсы без query-параметров; ссылки подтверждения почты и восстановления не попадают в кеш. Старые версии очищаются только среди кешей TeacherPro.

## Ограничения и риски, не закрытые автоматически

- Доступа к реальным политикам RLS, пользователям, SMTP и настройкам Supabase в ходе аудита не было. Проверка SQL-схемы выполнена по репозиторию; **её применение необходимо подтвердить отдельно**.
- Реальная визуальная проверка, тесты браузера на мобильных устройствах, сохранение при отключённой сети и end-to-end тесты по двум реальным сессиям пока не выполнены.
- PWA хранит локальные данные в `localStorage` без шифрования на уровне приложения. На общих/публичных устройствах следует выходить из аккаунта и использовать отдельные профили браузера; полного безопасного очищения старых копий пока нет.
- CSP с блокировкой inline JavaScript пока не внедрён: существующие HTML обработчики событий потребуют отдельного рефакторинга. При размещении публичной версии стоит выполнить отдельный XSS/CSP аудит.
- Нет автоматического объединения конкурирующих изменений двух устройств: конфликт требует выбора версии/ручного переноса данных.
- Telegram-рассылки не реализованы, клиентские токены не должны использоваться; в будущей версии секреты нужно хранить серверно и получать согласие адресатов.
- Не гарантирована работа внешних Google Fonts и CDN Supabase при сетевых ограничениях; есть системные запасные шрифты.
- Важная граница: никакие изменения в ветке аудита не следует объединять с `main` и деплоить без согласия владельца.

## Проверка реального Supabase (13.10.2026, подключённый проект)

Реально подключён и проверен проект `egopcojrzklvytcuhpov` (status: `ACTIVE_HEALTHY`). Запросы выполнялись **только на чтение**:

- `public.app_data` существует с колонками `user_id` UUID PK и FK на `auth.users`, `payload` JSONB, `updated_at` timestamptz.
- RLS **включён**; `anon` не имеет SELECT/INSERT/UPDATE; `authenticated` имеет SELECT/INSERT/UPDATE и не имеет DELETE.
- Ровно три политики SELECT, INSERT, UPDATE для `authenticated`, каждая ограничивает строки условием `auth.uid()=user_id`, на INSERT и UPDATE используется соответствующая `WITH CHECK`.
- `teacherpro_app_data_updated_at` — триггер BEFORE UPDATE. Тело `teacherpro_touch_app_data()` подтверждено: `greatest(clock_timestamp(), old.updated_at + interval '1 microsecond')`, `search_path=''`.
- Таблица содержит две строки, обе принадлежат отдельным владельцам; некорректного JSON нет, ключи `clients` и `settings` имеют корректный тип в обеих строках. Личные данные и payload не выводились.
- Advisor безопасности: **Leaked Password Protection Disabled**. Рекомендовано проверить доступность и включить проверку скомпрометированных паролей в Supabase Auth. Инструкция: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
- Advisor производительности: три замечания `auth_rls_initplan` (по одному на SELECT/INSERT/UPDATE). В ветке аудита `supabase/schema.sql` подготовлен вариант `(select auth.uid())=user_id`, но **изменения в базе не выполнялись**. Документация: https://supabase.com/docs/guides/database/postgres/row-level-security#call-functions-with-select

**Реальная конфигурация RLS подтверждена; отдельный end-to-end тест чтения/записи через два пользовательских JWT не проводился.** Реальная проверка восстановления пароля, доставки email и мобильного UI остаётся открытой.

Никаких деплоев, DDL, изменений пользователей и записей таблицы `app_data` в ходе этой проверки не выполнялось.
