# TeacherPro Owner Console

Владелец платформы получает отдельный рабочий интерфейс по адресу `/admin/`.
Кабинеты преподавателей остаются на `/`. Новых серверов или доменов не требуется:
HTML/JS/CSS развёртываются на существующем VPS, а административный backend
— Supabase Edge Function `teacherpro-admin`.

## Доступ и безопасность
- При каждом обращении API проверяет Supabase Auth JWT и роль в `tp_platform_admins`.
- Роль `owner` назначается **только доверенным серверным администратором** после
  верификации email владельца. Никогда не создавайте владельца по публичному signup.
- Преподаватель читает только собственную строку `app_data` через RLS.
- При приостановке через `tp_teacher_control` доступ к `app_data` закрывается
  и на клиенте, и в PostgreSQL. Никакие данные не удаляются.
- Таблицы конфигурации, админов, журнала, тарифов и поступлений доступны на
  запись только сервисному ключу серверной функции; в браузере такого ключа нет.
- Подробное содержимое карточек учеников **не включено** в административные API.
  Для последующего режима поддержки требуется отдельное согласие преподавателя.
- Изменения администратора регистрируются в `tp_admin_audit`.

## Возможности по этапам

1. **Роли и управление:** отдельный логин, кабинет владельца, список преподавателей,
   блокировка/восстановление облачного доступа, просмотр агрегированных данных аккаунта.
2. **Аналитика:** суммарное число учеников и занятий, начисления по проведённым
   занятиям, реальные поступления преподавателям, топ преподавателей,
   активность по последнему входу, Telegram-доставки. Начисления по
   историческим абонементам — оценка, а не гарантия полного восстановления истории.
3. **Настройки и поддержка:** глобальные объявления, включение/выключение
   обращений, статусы заявок, журнал админ-действий. Дополнительные переключатели
   для функций можно добавлять с серверной проверкой перед релизом.
4. **Монетизация:** каталог тарифов, их ручное назначение преподавателям,
   необязательный срок действия, отдельный журнал фактических поступлений
   самому TeacherPro. Поступления можно отменить, не удаляя историческую запись.
   **Автоматического эквайринга, чеков, рекуррентных платежей и реального
   ограничения функциональности по тарифу пока нет.** Эти части требуют
   подключения и согласования платёжного провайдера и бизнес-правил.

## Схема и обновления

- `supabase/owner-console.sql`
- `supabase/owner-console-permissions.sql`
- `supabase/owner-console-billing.sql`
- `supabase/owner-console-billing-reversal.sql`
- `supabase/functions/teacherpro-admin/index.ts`

В рабочем проекте Supabase соответствующие миграции применены, роль владельца
создана отдельно после сопоставления авторизованного GitHub владельца
с единственной совпадающей учётной записью Supabase. Не коммитьте emails,
пароли, токены или секретные сервисные ключи в миграции.

## Проверка перед релизом

- `node --test tests/owner-console.test.mjs`
- `node --check admin/admin.js`
- `node --check teacherpro-platform.js`
- `node --check app.js`
- CI `Owner Console Checks`, `TeacherPro pre-release checks`
- После публикации вручную войти владельцем в `/admin/` и проверить
  чтение данных, безопасный вход преподавателя, создание тестового обращения.
- Отдельно проверить учительские браузеры без VPN и мобильный вид.
- **Не** создавать тестовую запись получения денег в рабочем аккаунте.
