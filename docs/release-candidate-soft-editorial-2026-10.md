# TeacherPro — пакет к публикации: Soft Editorial «Тёплая студия»

## Что публикуется единым пакетом

- Новая главная с ближайшим занятием, загруженностью недели, круговой диаграммой и графиком часов по дням.
- Soft Editorial: кнопки, карточки, типографика, фирменный лист, оригинальный ботанический декор.
- Календарь в режимах «День», «Неделя» и «Месяц»; пропорциональная длительность, быстрые действия и сенсорное удержание.
- Корректное предупреждение и возврат списания при удалении проведённого занятия.
- Доставка всех файлов дизайна и JS-календаря с проверкой на сервере до переключения текущей версии.
- Предпубликационная GitHub Actions проверка синтаксиса, состава релиза и Playwright с фиктивными данными.

## Предпубликационные ограничения

1. Внешняя доступность домена без VPN ранее была нестабильна и намеренно отложена. Не путать её с работой интерфейса.
2. Playwright использует изолированный Supabase mock: реальные сессии, межустройственная синхронизация и физические жесты не покрыты.
3. Проверить реальные резервные копии Supabase и возможность восстановления перед крупными эксплуатационными изменениями.
4. До публикации удостовериться, что версия `main` не изменилась после проверки PR и что нет неразрешённых конфликтов.

## Порядок публикации (после отдельной команды владельца)

1. Убедиться, что проверки PR № 11 успешны, открыть и проверить скриншоты главной/календаря на 390 и 1280 px.
2. Перевести PR из черновика в обычный, выполнить squash merge в `main` только после команды владельца.
3. Дождаться `Deploy TeacherPro to VPS` (срабатывает на изменения приложения и deploy workflow в `main`).
4. Скрипт проверит наличие **каждого** файла на VPS до переключения симлинка `/srv/teacherpro/current`.
5. Скрипт проверит HTTPS и ключевые ресурсы через localhost на VPS. Результат GitHub Actions должен быть успешным.
6. Выполнить ручную проверку открывания главной, календаря, режима месяца, повторной авторизации и сохранения тестового занятия.
7. Проверить работу на телефоне. При проблемах остановить выпуск и вернуть предыдущий релиз.

## Откат (при подтверждённой необходимости)

На сервере остаются каталоги `/srv/teacherpro/releases/<commit-sha>`. Предыдущую версию можно восстановить через административную SSH-сессию, предварительно получив фактический SHA корректного релиза:

```bash
readlink -f /srv/teacherpro/current
ls -l /srv/teacherpro/releases
# Подставить подтверждённый SHA предыдущей исправной версии:
PREVIOUS="<previous-commit-sha>"
test -s "/srv/teacherpro/releases/$PREVIOUS/index.html"
ln -sfn "/srv/teacherpro/releases/$PREVIOUS" /srv/teacherpro/current-next
mv -Tf /srv/teacherpro/current-next /srv/teacherpro/current
```

Не удалять каталоги старых релизов до проверки нового. Откат файлов сайта **не заменяет** резервное копирование Supabase.
