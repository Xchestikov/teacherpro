# TeacherPro — контекст проекта и правила продолжения работы

Обновлено: 14 октября 2026. Этот документ нужно читать в начале нового чата вместе с актуальным кодом репозитория `Xchestikov/teacherpro`. Он не заменяет проверку текущего состояния GitHub, Supabase и работающего сайта.

## Цель продукта

Личный веб-кабинет преподавателя: ученики и их карточки, расписание и календарь, оплачиваемые заранее абонементы с фиксированным количеством занятий, посещаемость, домашние задания и **учёт полученных и ожидаемых оплат**. Используется с ПК и телефона; синхронизация между устройствами через Supabase.

**Не добавлять учёт расходов, категории «Материалы», расчёт чистой прибыли или другие инициативные функции без прямого согласования.** Это уже однажды было добавлено и по просьбе владельца удалено в PR #5.

## Технологии и инфраструктура

- Репозиторий: https://github.com/Xchestikov/teacherpro, рабочая ветка `main`.
- Приложение: статические `index.html`, `app.js`, `style.css`, `sw.js`, `cloud-config.js`, `manifest.webmanifest`, `icon.svg`; vanilla JavaScript + CSS. Есть service worker, поэтому при изменениях учитывай кеширование.
- Рабочий сайт: https://teacherpro-app.ru — FirstVDS Ubuntu 24.04, Nginx, HTTPS Let's Encrypt, каталог релизов `/srv/teacherpro/releases` и симлинк `/srv/teacherpro/current`.
- Auth и данные: Supabase project `egopcojrzklvytcuhpov`; авторизация email+пароль. Существующая модель синхронизирует JSON payload пользователя в `app_data`. Не менять рабочие данные и RLS без согласованной миграции и плана отката.
- `.github/workflows/deploy-vps.yml`: автоматический деплой изменений приложения в `main`, также `workflow_dispatch`; GitHub environment `production-vps`. **Слияние изменений приложения с `main` автоматически обновляет рабочий сайт.**
- `.github/workflows/monitor-production.yml`: проверка HTTPS, статических ресурсов и срока действия SSL каждые 6 часов; первая ручная проверка успешна.
- Старый проект Vercel остаётся резервным; **не удалять и не использовать как основную площадку без прямого решения владельца**.
- SSH: `teacherpro-admin` входит по персональному ключу и имеет sudo, вход root и SSH-пароли отключены, Fail2ban активен. UFW выключен, есть управляющие сетевые правила ISPmanager; по запросу владельца **не менять сетевые службы/firewall**.
- Supabase Free; первый `pg_dump` был создан на VPS (`~/teacherpro-backups/teacherpro-first.backup`), права `600`, файл читается через `pg_restore -l`. Это **не проверенное восстановление**, не зашифрованная внешняя копия. Автоматическое копирование отложено по просьбе владельца.
- Пароли, закрытые SSH-ключи, токены и пользовательские данные не записывать в эту документацию и не публиковать в GitHub.

## Непременные правила сотрудничества

1. **Перед каждой функциональной доработкой описывать предлагаемые фичи и согласовывать с владельцем.**
2. Разделять «подготовить в отдельной ветке» и «опубликовать». **Не сливать feature PR в `main` и не выкладывать на рабочий домен без отдельного согласия на публикацию.**
3. Сначала показать итог, сценарии и известные ограничения; затем пользователь решает, публиковать ли.
4. Не добавлять постороннюю бизнес-логику. Особенно не добавлять расходную часть финансов.
5. Не изменять живые данные Supabase, авторизацию, тарифы и сетевые параметры сервера без необходимости и согласования.
6. Новому чату начинать с прочтения этого файла, актуального `main`, открытых PR и фактического состояния CI.

## Согласованный план UX (14.10.2026)

Пример для главной страницы — присланный владельцем скриншот с карточками и графиком нагрузки; пример для календаря — скриншот быстрого меню действий поверх события.

**Первый этап (подготовка до согласования релиза)**:
1. Точная временная сетка: высота занятия строго пропорциональна 30/45/60/90/120 мин; правильное положение минут (например, 10:15), корректное размещение пересекающихся событий.
2. Нажатие на событие открывает компактное контекстное меню, не всю карточку. Управление статусом, переносом, редактированием и удалением — через меню.
3. На телефоне удержание события ~0,5 с включает перетаскивание; обычное короткое нажатие открывает меню. Учитывать скролл и невидимые части недельной сетки.
4. Главная: «Ближайшее занятие» с переходом к занятию, «Занятость недели» по дням с числом занятий и суммарными часами.
5. Кнопки: читаемые, единые размеры, хорошие цели касания и состояния; опасные операции подтверждаются.
6. Пропуски — **раздельные операции**: «Не пришёл без списания» и «Не пришёл со списанием». Списание при пропуске требует подтверждения. «Отмена без списания» не расходует абонемент. Предотвратить повторные списания и правильно возвращать занятие при изменении статуса.

### Текущая ветка работы над первым этапом

`feature/calendar-interactions-review-20261014` — **только подготовка, НЕ production**. Ветка содержит предварительные изменения `app.js` и `style.css`: пропорциональный календарь, макет меню, pointer-based mobile long press, обзор главной и статусы пропусков. Код требует проверки в браузерах и внимательных сценарных тестов списаний, особенно при изменении уже проведённого/списанного занятия. Не заявлять, что эта версия уже прошла E2E или мобильные тесты, пока не будут реальные результаты. Оформить PR для просмотра и лишь после одобрения владельца объединить с `main`.

- Улучшение карточки ученика и быстрых действий.

- Дополнительные улучшения главной страницы.
- Неопубликованные пожелания не считать согласованными задачами автоматически.

## Примечания для тестирования

- Проверить пересечение двух занятий разной длительности, расположение на 10:15 / 10:45 и события возле 23:00.
- Проверить перенос на рабочем столе и удержанием на телефоне, предотвращение случайного открытия/прокрутки.
- Проверить «проведён», «не пришёл со списанием», «не пришёл без списания», повторное переключение, возврат занятия и отсутствие двойного списания.
- Проверить, что другие страницы и старые данные продолжают работать; новая функциональность не требует изменений схемы Supabase.
- Сохранение на одном устройстве, обновление страницы и проверка на другом устройстве.
