# Доступ TeacherPro без VPN — план проверки

## Подготовлено
- Ограничение ожидания запросов авторизации и начальной загрузки данных в `app.js`.
- Шаблон Nginx `infra/supabase-nginx-location.conf` для проксирования запросов Supabase через FirstVDS.

## Перед включением прокси
1. На VPS проверить DNS, TLS и HTTPS к `egopcojrzklvytcuhpov.supabase.co`. Если VPS не может подключиться к Supabase, прокси не решит проблему.
2. Подготовить тестовый домен/конфигурацию Nginx и выполнить `nginx -t` перед reload.
3. Проверить пути `/supabase/auth/v1/health`, `/supabase/rest/v1/` и WebSocket `/supabase/realtime/v1/websocket`. Запросы к данным требуют ключа и пользовательского токена; не публиковать их в логах.
4. Настроить в клиенте `createClient` URL `https://teacherpro-app.ru/supabase` **только после** проверки прокси.
5. Убрать зависимость от jsDelivr: зафиксировать версию Supabase SDK, разместить проверенный bundle локально и обновить `index.html`, service worker и release manifest.
6. Проверить регистрацию, восстановление пароля, RLS, многосессионную синхронизацию, мобильный Safari, загрузку без VPN на мобильной сети.
7. Только после прохождения проверок включить прокси в рабочем Nginx и опубликовать клиентские изменения.

## Важно
Шаблон не активирован и сам по себе не меняет рабочий сервер. Изменение URL клиента до настройки прокси приведёт к отказу авторизации. Токены и service_role ключи не должны попадать в конфигурацию фронтенда или логи.
