# TeacherPro — личный кабинет преподавателя

Веб-приложение для личного использования: расписание, ученики, абонементы и оплаты. Развёртывается на Vercel, облачные данные хранятся в Supabase.

## Что реализовано
- Главная панель с цветными карточками показателей, быстрыми действиями, ближайшими занятиями, ожидаемыми оплатами и абонементами, требующими внимания
- Адаптивный дашборд для компьютера и телефона с отдельным пустым состоянием и пошаговым началом работы
- Недельный и дневной календарь, выбор даты, фильтр по ученику и быстрое создание и редактирование занятий
- Компактный календарь: визуально **одна строка на час** с точным выбором четверти часа (09:00, 09:15, 09:30, 09:45) при нажатии или перетаскивании и проверкой пересечений
- Проверка пересечений занятий с учётом длительности, подтверждение конфликтов и выбор длительности 30–120 минут
- Подтверждение отмены занятия и корректировка списаний при смене статуса или ученика
- Повторяющиеся занятия: каждую неделю или раз в две недели; каждому экземпляру назначается уникальный идентификатор
- Рабочая карточка ученика с вкладками «Обзор», «Домашние задания», «Заметки», «История», контактами Telegram, целью занятий и сводкой по оплатам и абонементам
- Журнал личных заметок по ученикам, домашние задания со сроком, ссылкой на материалы и статусами, копирование ДЗ для ручной отправки
- Общая очередь невыполненных и просроченных домашних заданий на главной странице
- Отдельные абонементы со стоимостью, сроками и остатком занятий
- Учёт оплат, включая ожидающие поступления; отметка оплаты как полученной/ожидающей, удаление ошибочной записи и обзор записей с датой в прошлом
- Автоматическое списание занятия при переводе в статус «Проведено» и возврат при отмене/переводе обратно; при неудачном списании изменение откатывается
- Регистрация, вход, повторное письмо подтверждения и восстановление пароля
- Синхронизация через Supabase и индикатор состояния в интерфейсе
- Экспорт и импорт резервной копии JSON
- Установка как PWA и кэширование оболочки приложения для повторного открытия
- Адаптивная мобильная навигация
- Аналитика дохода за последние 6 месяцев и счётчики проведённых/отменённых занятий
- Внутренний список задач: ожидаемые оплаты, абонементы с малым остатком и скорым окончанием срока, занятия на сегодня
- Автоматическая защита от повторного списания одного занятия при повторном вызове логики списания

## Архитектура
- Frontend: HTML, CSS, JavaScript
- Хостинг: Vercel
- Auth + cloud storage: Supabase Auth и таблица `public.app_data`
- Row Level Security: пользователь может читать и менять только собственную строку
- В браузере остаётся локальная копия, а облако является основной версией после входа

## Supabase setup
1. Создай Supabase-проект.
2. В SQL Editor выполни актуальный `supabase/schema.sql` **повторно после обновления**: SQL добавляет триггер серверной версии записи и настраивает RLS и права. Изменение файла в GitHub **само не меняет** уже существующую базу Supabase. Перед применением SQL сохрани резервную копию базы.
3. В Project Settings → API возьми Project URL и публичный publishable/anon key.
4. Заполни `cloud-config.js` значениями `RITM_SUPABASE_URL` и `RITM_SUPABASE_ANON_KEY`. **Никогда не помещай сюда service_role/secret key.**
5. В Authentication → URL Configuration укажи основной URL приложения в Site URL и добавь его в Redirect URLs.
6. В Authentication → Providers → Email можно временно отключить Confirm email для входа сразу после регистрации. Для обязательного подтверждения включи Confirm email; настрой Site URL и Redirect URLs из шага 5, а для реальной эксплуатации подключи собственный SMTP (встроенная почта Supabase строго ограничена по частоте). Приложение поддерживает оба режима и повторную отправку письма с интервалом не менее 60 секунд. Подтверждение должно обеспечиваться Supabase на сервере, не только интерфейсом.
7. Push в ветку `main` автоматически запускает деплой Vercel.

## Работа с данными
- Новый аккаунт начинает с пустого списка учеников, без демонстрационных клиентов.
- При первом входе нового пользователя создаётся пустая база. Локальная копия хранится по отдельному ключу для каждого user ID, а не общему для всех аккаунтов.
- Если облачная запись существует, она загружается на устройство.
- Экспортируй резервную копию перед массовым импортом или очисткой.
- Синхронизация отправляет изменения с небольшой задержкой, используя `updated_at` как версию записи: при параллельных изменениях приложение блокирует перезапись более новой облачной версии. Автоматического слияния изменений пока нет.
- Несинхронизированные изменения сохраняются локально для конкретного аккаунта (включая версию, от которой были сделаны правки) и восстанавливаются после повторного входа.
- Если возник конфликт версий, открой «Настройки»: скачай резервную копию локальных данных и выбери «Загрузить облачную версию (с резервной копией)» — это заменит локальную версию. Чтобы сохранить локальные правки, экспортируй JSON, затем загрузи актуальную облачную версию и вручную перенеси изменения или импортируй резервную копию целиком (при импорте текущие данные заменяются).
- Локальное хранилище браузера не зашифровано: не используй общедоступные устройства, очищай профиль браузера при передаче устройства другому человеку.
- При ошибке синхронизации проверь индикатор в верхней панели. Не считай данные сохранёнными в облаке, пока статус не подтвердит синхронизацию.

## Локальный запуск
Нужен локальный HTTP-сервер (не открывай HTML как `file://`, иначе Supabase/PWA могут работать некорректно):

```bash
python -m http.server 8080
```

Открой http://localhost:8080.

## Альтернативный хостинг без домена Vercel

Добавлен GitHub Actions workflow `.github/workflows/pages.yml`. После включения GitHub Pages сайт можно публиковать по адресу `https://xchestikov.github.io/teacherpro/`.

1. Открой Settings репозитория → Pages.
2. В разделе Build and deployment выбери **GitHub Actions** как источник.
3. Дождись workflow **Deploy static app to GitHub Pages** в разделе Actions.
4. В Supabase → Authentication → URL Configuration добавь в Redirect URLs адрес `https://xchestikov.github.io/teacherpro/**`.
5. Открывай сайт по GitHub Pages URL и проверь вход, письмо подтверждения и сохранение данных.

Это альтернативный адрес frontend. Если без VPN недоступен именно API Supabase, перенос frontend сам по себе этого не исправит — тогда понадобится отдельно проверить доступность `egopcojrzklvytcuhpov.supabase.co` и, возможно, сменить backend/провайдера.


## Предоплата абонементов
- При создании нового абонемента можно указать, оплачен ли он авансом или ожидает оплаты.
- Создание абонемента создаёт связанную запись в истории оплат; сумма учитывается в доходе только при статусе «Оплачено».
- Оплата привязана к конкретному абонементу. Изменение статуса оплаты синхронизируется с ним, повторная запись не создаётся при редактировании абонемента.
- Проведённое занятие списывается из оплаченного остатка; занятие нельзя впервые отметить проведённым, если нет оплаченного остатка.
- Нельзя удалить связанную запись предоплаты или вернуть её в ожидание, если по этому абонементу уже списывались занятия.
- Для старых данных, где у абонемента ещё нет поля статуса оплаты, сохраняется совместимость: такие абонементы считаются оплаченными.

## Пароли
- При новой регистрации и смене пароля требуется 8–72 символа, хотя бы одна буква и одна цифра, без пробелов, и подтверждение пароля.
- При входе существующие пароли не блокируются клиентской проверкой по новым правилам.
- Проверка в браузере нужна для удобства: для строгого серверного минимума отдельно настрой требования пароля в Supabase Auth (минимум 8 символов).

## Проверка безопасности и синхронизации
1. Проверь в Supabase Database → Tables → `app_data`, что RLS включён. Применить SQL из `supabase/schema.sql` необходимо вручную в правильном проекте.
2. Зарегистрируй два тестовых аккаунта. Ученик из первого аккаунта не должен появляться во втором. Проверь чтение и запись с обеих сессий.
3. Открой один аккаунт в двух разных браузерах, измени один и тот же профиль в каждом, сохрани сначала в первом, затем во втором. Во втором появится предупреждение о конфликте, а облачная версия первого не должна быть перезаписана.
4. Для проверки офлайна открой приложение, отключи интернет, внеси изменение, затем включи интернет. После успешной синхронизации оно должно появиться на другом устройстве. Если второе устройство успело обновить облако, появится конфликт.
5. При конфликте сначала экспортируй локальную резервную копию в «Настройках». После выбора облачной версии локальные изменения будут заменены.
6. Пользовательские данные могли быть перенесены между аккаунтами **до** исправления. Их нужно отдельно проверить в Supabase и при необходимости исправить вручную после резервного копирования. Новая логика не удаляет старые загрязнённые записи.

## Календарь и планирование
- Переключайся между «Неделя» и «День», используй дату для перехода и фильтр по ученику. Фильтр влияет только на отображение, не удаляет занятия.
- Перетаскивай **любое видимое занятие** (запланированное, проведённое, отменённое, пропуск или удалённый маркер) по времени и дням с шагом 15 минут, в том числе при нестандартной длительности 40 или 55 минут. На телефоне удерживай карточку около 0,45 секунды. Статус занятия, привязки к абонементу и уже выполненные списания при переносе не меняются. Активным занятиям запрещено пересекаться, а отменённые и удалённые маркеры не занимают слоты. Изменение сохраняется сразу; последнюю операцию можно отменить в уведомлении.
- Календарь показывает 05:00–00:00; последний урок должен закончиться не позже полуночи. Перенос проведённого урока меняет дату в истории/аналитике, но не списывает абонемент повторно. Изменение длительности перетаскиванием маркера остаётся доступным только для запланированных занятий.
- При создании серии повторений занятиям назначаются независимые ID, и каждое занятие можно редактировать отдельно. Массовое редактирование/удаление всей серии пока не реализовано.
- Для проверки: создай занятие, перемести между днями, проверь конфликт с другим занятием; создай серию и отредактируй её второй экземпляр; проверь списание и возврат оплаченного урока.

## Абонементы и финансы — этап 2
- В таблице абонементов есть сводка действующих оплаченных, требующих продления, ожидающих оплаты и общего количества пакетов.
- **Продлить** открывает новый абонемент с подставленным учеником, названием, количеством занятий и ценой. Старый пакет не изменяется; новая запись предоплаты создаётся ровно один раз.
- При редактировании существующего абонемента обновляется связанная запись предоплаты (сумма, плановая дата и описание), но не создаётся вторая. Если связанной записи нет в исторических данных, новая автоматически не создаётся.
- Учитывается число занятий, уже списанных по конкретному абонементу: нельзя поставить общее количество ниже списанного или остаток выше количества неизрасходованных занятий.
- Для новых полученных оплат записывается `paidAt` — фактическая дата поступления денег. Доход за месяц рассчитывается по `paidAt`, а старые записи без этого поля считаются по `date` (совместимость с историей).
- Для ожидаемых оплат поле `date` остаётся предполагаемой датой; дата в прошлом означает просрочку. При переводе в статус «Оплачено» записывается дата фактического получения.
- В «Оплатах» добавлены поиск, фильтр статусов и выгрузка CSV для Excel. Экспорт не меняет данные.
- Валидация цен, дат, количества и остатков работает до сохранения.
- Тестируй финансовую логику на отдельных тестовых аккаунтах, прежде чем редактировать реальные абонементы. Для локальных конфликтов синхронизации и ручного импорта сначала скачай резервную копию.

## Карточки учеников, домашние задания и заметки

- **Обзор**: имя, телефон, Telegram username (например `@student_name`), цель обучения, общие сведения, следующее занятие, действующий оплаченный абонемент, суммарные оплаты и домашние задания. Контакт Telegram открывается по ссылке, сообщение автоматически не отправляется.
- **Домашние задания**: тема, описание, срок, безопасная ссылка на материалы (http/https), статусы «Черновик», «Отправлено вручную» и «Выполнено». Кнопка «Скопировать для отправки» готовит текст для переписки; сама по себе она **не отправляет** сообщение и **не меняет** статус.
- **Заметки**: отдельные записи по каждому ученику, с темой, текстом и временем создания; они предназначены только для преподавателя. При редактировании сохраняется время последнего обновления.
- **История**: последние занятия и оплаты отдельной вкладкой.
- **Главная**: список заданий для контроля с выделением просроченных, быстрый переход в карточку соответствующего ученика.
- Данные `homework` и `studentNotes` сохраняются вместе с основной JSON-базой в Supabase `app_data`, отдельные таблицы и миграции для данного этапа не требуются. Старые базы дополняются пустыми массивами без удаления существующей информации.
- При удалении ученика также удаляются его личные заметки и домашние задания. Перед удалением делай резервную копию.
- Пока поддерживаются только **ссылки на файлы**, физическая загрузка файлов и автоматическая отправка в мессенджеры ещё не подключены. В дальнейшем потребуются Supabase Storage и серверный механизм отправки с согласиями получателей. Не добавляй в браузерный код токены ботов или секретные ключи.

### Краткие проверки

1. Создай двух тестовых учеников и для первого добавь ДЗ и заметку. У второго эти записи не должны отображаться.
2. Создай ДЗ со сроком в прошлом, проверь очередь на главной и отображение просрочки.
3. Измени статус «Выполнено», отредактируй текст, скопируй сообщение — оно должно попасть в буфер без автоматической отправки.
4. Выйди из аккаунта и войди заново; проверь сохранность записей и отсутствие записей из другого аккаунта.
5. Проверь вкладки и прокрутку карточки на узком экране. Полный браузерный тест требуется отдельно.

### Компактность календаря
- В сетке 15 часовых строк с 08:00 до 23:00 вместо 60 отдельных четвертей. Позиция указателя внутри часа определяет точное начало (`:00`, `:15`, `:30`, `:45`).
- При перетаскивании четверть часа подсвечивается без постоянного отображения дополнительных границ. События со временем 09:30 отображаются внутри часовой ячейки 09:00.
- Точное время можно также задать через редактор занятия. Это особенно удобно на устройствах без поддержки HTML5 Drag and Drop.

## Внешний вид и мобильная версия

- В настройках → **Фон и оформление** доступно шесть палитр кабинета: **Лавандовое утро**, **Шалфей**, **Тёплый персик**, **Тихий океан**, **Песчаный берег** и **Сумерки**. Тема меняет фон, акцент, элементы навигации и часть карточек. Выбранное значение сохраняется в `settings.theme` основного JSON-профиля и синхронизируется между устройствами.
- У существующих аккаунтов без сохранённой темы остаётся оформление **Лавандовое утро**. Неизвестные значения тем автоматически заменяются на безопасный вариант.
- На телефонах нижняя панель содержит пять основных разделов: Главная, Расписание, Ученики, Абонементы, Оплаты. **Настройки** доступны кнопкой ⚙ в верхней панели, чтобы не делать шесть тесных пунктов внизу.
- На планшете боковая панель компактно показывает пиктограммы, на большом экране — полные названия.
- Модальные окна на телефоне открываются как нижняя панель, с прокруткой и сохранением доступа к кнопкам. Таблицы прокручиваются горизонтально внутри своих контейнеров, не раздвигая страницу. Календарь остаётся компактным по высоте, с почасовыми ячейками и точностью 15 минут при выборе времени.
- Палитры выполнены стилями CSS: не загружаются изображения-фоны, что сокращает вес страницы и снижает визуальный шум. Темная тема предназначена для вечернего использования.
- Предусмотрены фокус клавиатуры и отключение части анимаций в режиме `prefers-reduced-motion`.
- Полноценные браузерные smoke-тесты на реальных устройствах и разных масштабах следует провести дополнительно.

### Что проверить после деплоя
1. Сменить тему в Настройках, перезагрузить страницу и войти с другого устройства в тот же аккаунт.
2. Проверить на 320, 360, 390, 768 и 1280 px: нижняя навигация и кнопка настроек, формы, карточка ученика, таблицы оплат, календарь в режимах «День» и «Неделя».
3. Открыть большую карточку ученика и редактор домашнего задания на телефоне; проверить прокрутку формы и доступность кнопок внизу.
4. Проверить тёмную тему на текстах, карточках, статусах и индикации синхронизации.

## Атмосферный кабинет — фон, шрифты и дни рождения

- В **Настройки → Фон кабинета** добавлено 12 фактурных пресетов: «Чистый лист», «Лён», «Мятая бумага», «Мрамор», «Тетрадь», «Песок», «Облака», «Оливковый», «Известняк», «Акварель», «Бордо», «Ночной холст». Фактуры создаются CSS без тяжёлых изображений, а не загружаются как фотографии.
- Фон и цвет акцентов настраиваются независимо; к прежним палитрам добавлена «Бордовый бархат». Сохраняются в аккаунте как `settings.background` и `settings.theme` и синхронизируются обычным сохранением данных.
- Используется **Manrope** для основного UI и **Playfair Display** для крупных редакционных акцентов, с системными запасными шрифтами. Внешние шрифты загружаются через Google Fonts; если сервис недоступен, работают локальные системные замены.
- На главной появились крупные виджеты **уроки сегодня** и **доход за месяц**, а также блок **дни рождения**. День рождения ученика открывает его карточку.
- В карточке ученика день рождения можно указать как `ДД.ММ` или `ДД.ММ.ГГГГ`, год необязателен. Отсутствие даты допустимо. Проверка не допускает невозможные даты, для 29 февраля ближайший день рождения приходится на следующий високосный год.
- Блок ближайших дней рождения показывает события в пределах 30 дней; если событий нет, выводит ближайший следующий день рождения или предложение заполнить даты.
- У ранее созданных учеников поле необязательно; старая база продолжает открываться без миграций. В старых аккаунтах без сохранённого фона используется «Лён».

### Сценарии проверки

1. Открой Настройки, попробуй несколько фоновых фактур и цветовых тем, перезагрузи страницу.
2. Добавь в карточке ученика `31.12` и `29.02`, проверь даты в блоке дней рождения на главной.
3. Создай ученика без даты и ученика с датой `31.02`: первый сохраняется, второй должен вызвать подсказку об ошибке.
4. Проверь главную, страницу настроек и карточку ученика на мобильном экране, особенно читаемость на «Бордо» и «Ночном холсте».
5. Подтверди синхронизацию в облаке перед выходом или открытием кабинета с другого устройства.
